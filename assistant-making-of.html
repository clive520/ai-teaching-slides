幕後花絮：專屬教學助手

這一次，我們沒有直接開始寫程式。
我們採用了 RDQ 需求四象限法 (Requirements Discovery Quadrant) 進行了精準的需求訪談，確保開發方向百分之百切中要害。

我們先來討論一下「專屬教學助手」這個部分該如何呈現，以及它要做的工作會是什麼？

先跑一次「RDQ (需求探索四象限法) 需求訪談」。

【象限 III & IV】AI 發動結構化訪談

太棒了！為了最快幫您收斂想法並聚焦功能，請回答以下 3 個問題：

  1. 實作深度：您希望做到 真實串接 API 還是 介面模擬？
  2. 助手人設：職責偏向 課程知識庫、蘇格拉底導師、還是 萬能助教？
  3. 建議菜單 (可複選)：加入預設提問按鈕？加入字數限制？

1. 要真實串接各項 AI 的 API，我想做後臺的輸入... 可以輸入 OpenCode、ChatGPT、NVIDIA、Gemini 的 API。

2. 我想做出選項，在老師呼叫這位教學助手前，可以設定他是屬於哪一類型的，因為這三類型在課堂上都會用到。

3. 採網頁輸入 API Key，可以先不管詢問次數。但可以給預設提問按鈕。

【產出規格】AI 自動產生規格卡

收到！您的需求非常明確，因為是讓老師自備金鑰，所以我們不需要擔心被刷爆費用的問題！以下是為您整理的需求規格卡：

📌 核心定位
打造一個可在課堂上靈活切換角色，支援多模型串接的 AI 教學助手網頁。

📝 具體規格
  • 後台設定：支援 ChatGPT, NVIDIA, Gemini, OpenCode 的金鑰與 Endpoint 設定。
  • 三大人設切換：課程知識庫、蘇格拉底導師、萬能助教。
  • 前端互動：附帶「快速提問按鈕」降低發問門檻。

確認規格後，AI 僅花了不到 1 分鐘，就生成了完整的 HTML/JS/CSS，並完成 4 種不同 AI API 的串接邏輯！
